# 게시글 목록 페이지네이션 문제 해결 기록

**날짜**: 2025년 7월 21일  
**담당자**: Claude Code  
**문제 유형**: 프론트엔드 페이지네이션 기능 오류  

## 🚨 문제 상황

### 증상
- 게시판 페이지에서 모든 게시글이 표시되지 않음
- 2페이지에 해당하는 게시글만 표시됨
- 총 49개의 게시글이 있지만 일부만 보임

### 사용자 보고
> "게시글 목록에 모든 게시글이 나타나지 않고 있어. 현재는 2페이지에 해당하는 게시글만 표시되고 있어."

## 🔍 문제 분석 과정

### 1단계: 현재 구현 코드 분석
- **파일**: `frontend/app/hooks/useListData.ts`
- **발견된 문제**: API 호출 시 페이지 번호가 고정됨

```typescript
// ❌ 문제가 있던 코드
const response = await apiClient.getPosts({
  ...config.apiFilters,
  page: 1,        // 항상 1페이지만 요청
  size: 50        // 50개 제한
});
```

### 2단계: 백엔드 API 검증
- **API 엔드포인트**: `/api/posts`
- **파라미터**: `page`, `page_size`, `metadata_type`
- **테스트 결과**: 백엔드는 정상적으로 페이지네이션 지원

```bash
# API 테스트 결과
=== Page 1 ===
Status: 200
Total items: 49
Page: 1
Items count: 10

=== Page 2 ===
Status: 200
Total items: 49
Page: 2
Items count: 10
```

### 3단계: 아키텍처 문제 식별
- **근본 원인**: 클라이언트 사이드 페이지네이션과 서버 사이드 페이지네이션의 혼재
- **중복 구현**: 
  - `UnifiedPostList` 컴포넌트 내부의 로컬 페이지네이션
  - `useListData` 훅의 불완전한 서버 사이드 페이지네이션

## 🛠️ 해결 방안

### 핵심 전략
서버 사이드 페이지네이션으로 완전 통일하여 데이터 일관성 확보

### 구현 변경사항

#### 1. `useListData.ts` 훅 개선
```typescript
// ✅ 개선된 코드
export interface UseListDataResult<T extends BaseListItem> {
  // 페이지네이션 상태 추가
  currentPage: number;
  totalPages: number;
  totalItems: number;
  pageSize: number;
  handlePageChange: (page: number) => void;
}

// 동적 페이지 호출
const fetchData = useCallback(async (page: number = 1) => {
  const response = await apiClient.getPosts({
    ...config.apiFilters,
    page: page,        // 동적 페이지 번호
    size: pageSize     // 설정 가능한 페이지 크기
  });
});
```

#### 2. 페이지별 캐싱 시스템 구현
```typescript
// 페이지별 캐시 키 생성
const cacheKey = `${getCacheKey()}-page-${page}`;

// 캐시 데이터 구조 개선
CacheManager.saveToCache(cacheKey, {
  items,
  total: response.data.total || 0,
  page: response.data.page || page,
  pageSize
}, 5 * 60 * 1000);
```

#### 3. `UnifiedPostList` 단순화
```typescript
// ❌ 제거된 로컬 페이지네이션
const [currentPage, setCurrentPage] = useState(1);
const totalPages = Math.ceil(posts.length / postsPerPage);
const currentPosts = posts.slice(startIndex, endIndex);

// ✅ 단순한 리스트 렌더링
return (
  <div className="post-list">
    {posts.map((post) => (
      <UnifiedPostListItem key={post.id} post={post} onClick={onItemClick} />
    ))}
  </div>
);
```

#### 4. UI 통합 및 개선
```typescript
// UnifiedListPage.tsx에서 통합 페이지네이션
<UnifiedPagination
  currentPage={currentPage}
  totalPages={totalPages}
  onPageChange={handlePageChange}
/>
```

## 📊 성능 최적화

### 캐싱 전략
- **페이지별 독립 캐싱**: 각 페이지를 개별적으로 캐시
- **백그라운드 업데이트**: 캐시된 데이터 표시 후 백그라운드에서 최신 데이터 갱신
- **TTL 설정**: 5분간 캐시 유지

### UX 개선사항
- **페이지 변경 시 스크롤 상단 이동**: `window.scrollTo(0, 0)`
- **기존 UI 디자인 유지**: `UnifiedPagination` 컴포넌트 사용
- **맨앞/맨뒤 버튼**: 첫 페이지/마지막 페이지 직접 이동
